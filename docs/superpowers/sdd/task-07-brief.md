# Task 7 — Projects: share, explore, detail, join requests, invites, team management

Read `docs/superpowers/sdd/global-constraints.md` and `docs/design-system.md` first. Spec sections: §2 (who sees what), §4.3, §4.4, §4.8 (notification types), §8.
Available: `db`, auth guards, `ActionResult` helpers, `notify`/`notifyMany`, `displayName`, `toSearchText`, `parseList`/`toListJson`, taxonomy (`CATEGORIES`, `STAGES`, `WORK_MODES`, `DISCIPLINE_GROUPS`, `CITIES`, `labelOf`), DTOs (`ProjectCardData`, `projectCardInclude`, `toProjectCardData`, `personSummarySelect`, `toPersonSummary`), components (`ProjectCard`, `DisciplineSpine`, `DisciplineChip`, `VerifiedStamp`, `UserRow`, all UI primitives incl. `Sheet`), `relativeTimeTr`. Stubs exist for `/paylas`, `/projeler`, `/projeler/[id]`, `/projeler/[id]/duzenle` — replace them.

## 1. Library — `src/lib/projects/`
- `schemas.ts` (zod, shared by client and server, no server imports): `projectInputSchema` — title 8–80, summary 20–160, description 80–4000, category/stage/workMode from taxonomy, city required when workMode is YUZ_YUZE or HIBRIT and must be in `CITIES` (null for UZAKTAN), tags 0–8 items each 2–30 chars, roles 1–6 items `{ id?: string, title 3–60, disciplineGroup (taxonomy id), slots int 1–5, description 0–200 }`. `applySchema` — roleId optional, message 20–1000. `inviteSchema` — projectId, username, roleId optional, message 0–500. Turkish error messages.
- `queries.ts`:
  - `listProjects({ q?, category?, disciplineGroup?, workMode?, city?, stage?, page = 1, pageSize = 12, ownerOrMemberId? })` → `{ items: ProjectCardData[]; hasMore: boolean }`. Only `status: "OPEN"` unless `ownerOrMemberId` is set (then the user's own/member projects, any status). `q` → AND of `searchText contains token` for `searchTokens(q)`. disciplineGroup filter → projects having a role with that group. Newest first.
  - `getProjectDetail(id, viewer: CurrentUser | null)` → project with owner (person summary), roles (with `filled` = members holding that role), members (person summaries + role title + isOwner), counts; plus viewer-specific state: `isOwner`, `isMember`, `pendingRequest` (viewer's PENDING JoinRequest), and for the owner: pending JoinRequests (applicant person summary, role, message, createdAt) and pending invites (invitee summary, role). Returns null if not found.
  - `getViewerOpenProjectsForInvite(viewerId)` → viewer's OPEN projects with roles (used by profile page in task 8).
- `actions.ts` (`'use server'`; every action: verified user required → otherwise `fail("Bu işlem için belgeni doğrulaman gerekiyor.")`; ownership checks return `fail("Bu işlem için yetkin yok.")`):
  - `createProjectAction(prev, formData)` — parse JSON payload field `payload` (the client form serialises roles/tags) with `projectInputSchema`; create project + roles + owner `ProjectMember` (isOwner true) in a transaction; `searchText = toSearchText(title, summary, description, tags, role titles, role discipline labels, category label, city)`; `notifyMany(followerIds, { type: "NEW_PROJECT_FROM_FOLLOWING", actorId, projectId })`; redirect `/projeler/<id>?yeni=1`.
  - `updateProjectAction(projectId, prev, formData)` — owner only; update fields; roles: update existing by id, create new, delete removed roles only if no member holds them (else fail "Üyesi olan bir rol silinemez."); refresh searchText; redirect to detail.
  - `setProjectStatusAction(projectId, status: "OPEN" | "CLOSED")`, `deleteProjectAction(projectId)` (owner; confirm in UI; redirect `/projeler?filtre=benim`).
  - `applyToProjectAction(projectId, prev, formData)` — project OPEN; not owner/member; no existing PENDING request; role (if given) belongs to project and is not full; blocked either way with owner → fail "Bu projeye başvuramazsın."; create JoinRequest; notify owner JOIN_REQUEST.
  - `withdrawApplicationAction(requestId)` — applicant only, PENDING → WITHDRAWN.
  - `decideApplicationAction(requestId, decision: "ACCEPT" | "REJECT")` — owner only; ACCEPT: role not full (else fail "Bu rolün kontenjanı dolu."), create ProjectMember (roleId), request ACCEPTED, notify applicant JOIN_ACCEPTED; REJECT: REJECTED + notify JOIN_REJECTED.
  - `inviteToProjectAction(prev, formData)` — owner only; invitee by username must be VERIFIED, not blocked either way, not already member, no PENDING invite for same project; create ProjectInvite; notify invitee INVITE.
  - `cancelInviteAction(inviteId)` — owner; PENDING → CANCELLED.
  - `respondToInviteAction(inviteId, response: "ACCEPT" | "DECLINE")` — invitee only, PENDING; ACCEPT: project must be OPEN, role not full, create member, ACCEPTED, notify inviter INVITE_ACCEPTED; DECLINE: DECLINED, notify INVITE_DECLINED. (Task 8's Network page calls this.)
  - `leaveProjectAction(projectId)` — member, not owner.
  - `removeMemberAction(projectId, userId)` — owner, cannot remove self.
  - `searchInvitableUsersAction(projectId, query)` — owner only; returns up to 8 verified users (person summaries) matching `searchText`, excluding members, blocked users and self.
  - All mutating actions `revalidatePath` the affected pages.

## 2. Pages
- `/paylas` — `requireVerified("/paylas")`. Client form `src/components/projects/project-form.tsx` (also used by edit): sections Temel bilgiler (başlık, kısa özet with live counter, açıklama), Kategori ve aşama (native selects or chip pickers), Çalışma şekli (segmented control; city select appears for Yüz yüze/Hibrit), Etiketler (type + Enter to add chips, max 8), **Aranan roller** (repeatable cards: rol adı, disiplin select showing color dot, kişi sayısı stepper 1–5, kısa açıklama; "Rol ekle" up to 6; remove button). A live preview strip of the discipline spine (horizontal) built from the selected role groups sits above the roles list. Submit "Projeyi paylaş" (edit: "Değişiklikleri kaydet"). Client-side validation with the same zod schema; field errors from the server shown inline. Short intro line: "Yalnızca proje paylaşılabilir. Ekip arkadaşı aradığın gerçek bir proje anlat."
- `/projeler` — public. PageHeader "Projeler". Filter bar: horizontal scrollable chips for disciplines (with dots) + a "Filtreler" button opening a Sheet (kategori, çalışma şekli, şehir, aşama) — all state in URL params (`kategori`, `disiplin`, `calisma`, `sehir`, `asama`, `q`, `sayfa`, `filtre=benim`). Active filter count on the button and a "Filtreleri temizle" link. List of `ProjectCard`; "Daha fazla göster" link to next page. `filtre=benim` (requires user) titled "Projelerim" showing own + member projects incl. closed. Empty state with action ("Filtreleri temizle" or "İlk projeyi paylaş").
- `/projeler/[id]` — public (notFound if missing). Layout: horizontal DisciplineSpine band at top; title `.t-page`; chips (category, stage, work mode, city, status); owner row (avatar, `displayName(owner, viewer)`, stamp, university; links to profile only for verified viewers); description with preserved line breaks; **Aranan roller** list (title, discipline chip, "2/3 dolu" counter, description, full roles marked "Dolu"); Ekip (members); tags. `?yeni=1` → success banner "Projen yayında. Takipçilerin ana sayfalarında görecek."
  Primary action area (sticky above bottom nav on mobile): guest → "Katılmak için giriş yap" (`/giris?next=/projeler/<id>`); unverified → "Katılmak için belgeni doğrula" (`/dogrulama`); verified non-member → "Projeye katıl" opens Sheet with role select (only non-full roles) + motivation textarea (counter, min 20) + "Başvuruyu gönder"; pending → "Başvurun değerlendiriliyor" + "Başvuruyu geri çek"; member → "Ekiptesin" + "Projeden ayrıl" (confirm) + "Ekiple mesajlaş" is NOT needed; closed project → "Bu proje yeni başvuru almıyor."
  Owner panel (below, only for owner): Başvurular (each: UserRow with message, role, "Kabul et" / "Reddet"), Davet et (Sheet: search input calling `searchInvitableUsersAction` with 300 ms debounce, role select, optional message, "Davet gönder"), Bekleyen davetler (with "Daveti geri al"), Ekip (remove member), and actions "Düzenle", "Başvurulara kapat"/"Başvurulara aç", "Projeyi sil" (confirm dialog).
- `/projeler/[id]/duzenle` — owner only (else notFound); ProjectForm prefilled.
