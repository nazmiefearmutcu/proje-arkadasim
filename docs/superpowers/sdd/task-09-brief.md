# Task 9 — Messaging with message requests

Read `docs/superpowers/sdd/global-constraints.md` and `docs/design-system.md` first. Spec sections: §4.7 (binding rules), §8 (polling, rate limits).
Available: `canMessageDirectly`, `isBlockedEitherWay`, `notify`, `rateLimit`/`LIMITS`, auth guards, `assertSameOrigin`, DTO person summaries, `relativeTimeTr`, UI primitives, `useCounters` store (task 3) and `getCounters` semantics: a conversation is unread for a user when it is ACTIVE and has a message from the other participant newer than that user's `ConversationRead.lastReadAt`. Stubs exist for `/mesajlar`, `/mesajlar/[id]` — replace them; create `/mesajlar/yeni`.

## 1. Library — `src/lib/messaging/`
- `service.ts` (plain server functions, unit-testable):
  - `pairKey(a, b)` → `[userAId, userBId]` sorted so `userAId < userBId`.
  - `findConversation(a, b)`.
  - `startConversation(senderId, recipientUsername, body)` → `{ conversationId }` or error. Rules: recipient exists and VERIFIED; not self; not blocked either way (error "Bu kişiye mesaj gönderemezsin."); body 1–2000 chars after trim; rate limit `message:<senderId>`. If a conversation already exists → delegate to `sendMessage`. Else create with status ACTIVE if `canMessageDirectly`, otherwise REQUEST with `initiatorId = sender`; insert the first message; set `lastMessageAt`; upsert sender's ConversationRead; for REQUEST → `notify(recipient, "MESSAGE_REQUEST", actorId, conversationId)`.
  - `sendMessage(senderId, conversationId, body)` → message DTO or error. Sender must be a participant; not blocked either way. If status REQUEST or DECLINED and `canMessageDirectly` is now true → promote to ACTIVE first. Then: ACTIVE → allowed. REQUEST and sender is initiator → error "İsteğin kabul edilene kadar yeni mesaj gönderemezsin."; REQUEST and sender is recipient → error "Önce mesaj isteğini kabul et."; DECLINED and sender is initiator → same error as pending REQUEST (do not reveal the decline); DECLINED and sender is recipient → error "Bu isteği reddettin." Insert message, update `lastMessageAt`, upsert sender ConversationRead to now.
  - `acceptRequest(userId, conversationId)` — user is the non-initiator participant, status REQUEST → ACTIVE; notify initiator MESSAGE_REQUEST_ACCEPTED.
  - `declineRequest(userId, conversationId)` — REQUEST → DECLINED (no notification).
  - `listConversations(userId, kind: "chats" | "requests")` — chats: ACTIVE conversations, plus REQUEST/DECLINED conversations the user initiated (shown as "İstek gönderildi"); requests: REQUEST conversations where user is the recipient. Each row: id, other participant (person summary), last message preview (body truncated 80, "Sen: " prefix when own), lastMessageAt, unread boolean (per the semantics above), status, isInitiator. Exclude conversations with blocked users. Order by lastMessageAt desc.
  - `getConversationForUser(userId, conversationId)` — participant check (else null), other person, status, isInitiator, blocked flag, last 50 messages ascending.
  - `getMessagesAfter(userId, conversationId, afterIso)` — participant check; messages with createdAt > after, max 100; also upserts the viewer's ConversationRead to now (marks read).
  - `markRead(userId, conversationId)`.
- `actions.ts` (`'use server'`, verified required): `startConversationAction(prev, formData)` (redirects to `/mesajlar/<id>` on success), `sendMessageAction(conversationId, body)` → `ActionResult<MessageDTO>`, `acceptRequestAction(id)`, `declineRequestAction(id)` (redirect `/mesajlar?sekme=istekler`).
- `src/app/api/conversations/[id]/messages/route.ts` — GET `?after=<ISO>`; 401 for guests, 404 for non-participants; returns `{ messages: MessageDTO[], status }` where `MessageDTO = { id, body, createdAt (ISO), mine: boolean }`. `dynamic = "force-dynamic"`.
